Short-Term Memory

What is EMA?

EMA — Exponential Moving Average — is the engine's short-term memory of how much a product typically sells per day. It's the single most important number in the baseline forecast.

🧠 The Simple Idea

Imagine you sell a medicine every day. Instead of using the raw sales number from just yesterday (too noisy) or a plain average of the last 6 months (too slow to react), the EMA finds a middle ground:

  • → Recent days matter more
  • → Older days matter less (they fade out gradually)
  • → A single freak day (e.g. a huge bulk purchase) doesn't break the forecast

📐 The Formula

EMAtoday = α × Salestoday + (1−α) × EMAyesterday
α = 0.30 30% weight goes to today's actual sales — recent reality matters.
(1−α) = 0.70 70% weight stays with yesterday's EMA — preserving accumulated memory.

⚡ Spike Guard

If today's sales are more than 1.8× the previous EMA (a suspected data glitch or bulk order), the system caps the input at 1.4× before updating. This prevents one abnormal day from corrupting weeks of learned memory.

Velocity Intelligence

Every SKU Gets a Behaviour Label

Before any model runs, the system classifies each product's recent sales speed. This label controls which models activate and how aggressive the predictions are.

💀 Dead 0 sales

No meaningful demand in last 15 days, or inactive for 7+ days. Forecast output: 0 units.

Models active: None
🐢 Slow < 0.5/day

Rare, sporadic demand. The system uses only the simple EMA baseline — statistically noisy enough to skip complex models.

Models active: EMA only
🚶 Medium 0.5–3/day

Consistent, regular sellers. SARIMA activates to learn weekly patterns and trends. Blended 65% baseline / 35% SARIMA.

Models active: EMA + SARIMA
🚀 Fast ≥ 3/day

High-volume, high-confidence SKUs. All three layers run. Blended 35% baseline / 45% SARIMA / 20% ML.

Models active: EMA + SARIMA + ML
🛡️ Override Safety Guards Applied after classification
Zero-Sales Guard
If last 7 days = 0 units, velocity is capped at Slow, blocking SARIMA/ML.
Demand Collapse Guard
Last 7-day average < 50% of the prior 14-day average → forced Slow + EMA reset.
Inactivity Guard
If stored last-sale-date is 7+ days ago, velocity overridden to Dead regardless.
Statistical Intelligence

How SARIMA Works

SARIMA is a statistical model that studies the shape of past sales — cycles, rises, falls — and projects that shape into the future. Think of it as a very experienced analyst who spots patterns in spreadsheets.

📐 SARIMA Parameters Explained

SARIMA(p, d, q)(P, D, Q, s)
s = 7 (weekly seasonality)
p
Past Sales Influence
How many previous days' sales directly influence today's prediction. If p=2, yesterday and the day before both matter.
d
Trend Removal
How many times the data is "differenced" to remove long-term trends, so the model focuses on the fluctuations.
q
Error Smoothing
Uses past prediction errors to improve future predictions. Helps the model self-correct from its own mistakes.
s
Seasonal Period = 7
Tells the model that sales repeat in weekly cycles. Mondays look like last Monday; Fridays look like last Friday.

🔍 What SARIMA Detects

📈
Trends
If a medicine is steadily gaining popularity month over month, SARIMA captures this upward trajectory.
🔁
Seasonality
Winter cold medicines spike every year. SARIMA remembers these recurring patterns and applies them to the forecast.
📅
Weekly Cycles
Pharmacies sell more on certain weekdays. SARIMA's s=7 setting means it always "remembers" what day of the week it is.
Weekly Seasonality Pattern Detected by SARIMA

SARIMA automatically detects Friday peaks and Sunday dips — no configuration needed.

Real Example

If Napa Extra 500mg consistently sells 30 units every Friday (payday effect) but only 15 units on Sundays, SARIMA will automatically forecast higher quantities for upcoming Fridays — without any human configuration required.

⚠️ SARIMA only activates when a SKU has at least 21 days of history and is classified as medium or fast. For newer products, the system relies on the EMA baseline.
Machine Learning Layer

The AI Correction Layer

SARIMA knows patterns from the past. ML goes further — it learns complex relationships between many signals that no single formula can capture. It acts as a smart correction on top of the statistical forecast.

🎯

Step 1 — Will It Sell?

A classifier model first asks: "Will this product sell at all on this day?" It outputs a probability score (0–100%). If the probability is below the threshold, the forecast is set to zero — preventing phantom orders.

Threshold: 35% probability. Below this = no sale predicted.
🔢

Step 2 — How Much?

If the classifier says "yes, it will sell", a regressor model then predicts the exact quantity. It considers weekday patterns, recent lag features, seasonality signals, and event relationships simultaneously.

Minimum history: 30 days required before ML activates.
⚡

Step 3 — Blend with Others

For fast-moving SKUs, ML contributes 20% of the final forecast. SARIMA contributes 45% and the EMA baseline 35%.

EMA Baseline35%
SARIMA45%
ML20%
Only for: Fast-velocity SKUs (≥ 3 units/day average).

What ML Detects That Rules Cannot

📊
Demand Spikes
Sudden surge in demand that breaks the usual pattern — like a disease outbreak or a major promotion.
📉
Declining Products
Products being phased out or replaced by alternatives — steady decline that SARIMA might over-estimate.
🔀
Complex Interactions
Payday + weekend + post-holiday all happening simultaneously — non-linear combinations a formula misses.
🆕
New Growth
Products gaining momentum — where historical averages understate future demand and the trend is accelerating.

Technical Stack

Built on Industry-Proven Tools

Every component was chosen for reliability at scale in production retail environments.

Python 3.11
Core runtime

The entire engine — data loading, modelling, and database writes — runs as a single Python process. Designed for Python 3.10 or 3.11.

🐼
Pandas
Data wrangling

All sales data is represented as time-indexed Pandas Series. Daily resampling, gap filling, and rolling windows are Pandas native operations.

📈
statsmodels
SARIMA engine

SARIMAX from statsmodels fits the seasonal ARIMA model. pmdarima's auto_arima automatically selects the best p,d,q parameters per SKU.

🤖
scikit-learn
ML layer

The optional ML layer uses scikit-learn compatible classifier and regressor models. Any sklearn-compatible model can be plugged in without code changes.

🗄️
SQLAlchemy + MySQL
Persistence layer

All reads and writes go through SQLAlchemy with connection pooling. Bulk upserts write 5,000 rows per batch. Production uses an SSH tunnel via sshtunnel.

⏱️
Cron / systemd
Scheduling

The engine runs as a scheduled daily job. All writes are upsert-safe — re-running any time is safe and will overwrite the existing forecast for the same date.

⚡
Performance at Scale

With 3–4k active SKUs, a typical daily run completes in 2–6 minutes (baseline + SARIMA). With ML enabled: 4–10 minutes. Each failed SKU is isolated — one error cannot crash the entire batch.
